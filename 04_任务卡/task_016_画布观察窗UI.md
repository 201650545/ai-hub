# 任务卡 016：画布观察窗 UI

## 执行模型：🟢 Gemini 3.6 Flash

## 目标
实现组件编排器的画布观察窗——AI 工作过程的实时动画式展示界面，让人类可以观察运作方式、监控进度、查看每部分的预览截图。

## 架构依据
`D:\项目\06_组件编排器\组件编排器架构设计.md` §8（事件流协议已定）。
**性质：只读观察 + 监控，不是编辑器。**

## 交付物
`D:\项目\06_组件编排器\canvas\` 下：
- `index.html` — 画布页面
- `styles.css` — 深色科技风样式
- `app.js` — SSE 消费与渲染逻辑

## 界面要素

### 1. 阶段时间线（顶部）
framework → scan → asset_fill → verify → deliver 五阶段，当前阶段高亮呼吸动画，已完成打勾。

### 2. 槽位状态格（主体）
每个媒体槽位一个卡片，实时状态：
- ⏳ 待处理（灰）/ 🔄 生成中（蓝，呼吸动画）/ ✅ 完成（绿）/ ⚠️ 重试中（黄）/ ❌ 失败（红）
- 卡片显示：槽位 id、topic、站点名、耗时
- 完成卡片内嵌**预览截图**（图片缩略图 / 视频 iframe 首帧）

### 3. 事件流日志（侧栏）
滚动展示 SSE 事件（时间 + 事件 + 详情），失败事件红色高亮。最新事件自动滚动到底。

### 4. 控制条（底部）
- L2 档位的确认按钮（框架确认 / 槽位清单确认 / 继续）
- 整体进度条（done/total）与已用时间

## 技术约定
- SSE 端点：编排器通过 `GET /api/orchestrator/stream` 推送（task_013 的事件流；若该端点未就绪，先用 `mock_events.js` 模拟数据开发）
- 事件 JSON 字段严格按 §8：`{ts, phase, slot, event, detail}`
- 预览截图路径：事件 detail 中的相对路径，直接 `<img src>` 引用
- 纯 HTML/CSS/JS 无框架，风格与 `00_中央平台\dashboard\` 保持一致（深色毛玻璃科技风）
- 响应式：1280px 与 1920px 两档布局正常

## 验收标准
- mock 数据下五阶段流转、槽位状态变化、截图展示全部正常
- 事件流日志实时滚动，无卡顿（100 条事件内）
- L2 确认按钮可触发（发 POST /api/orchestrator/confirm）
- 失败/重试事件视觉区分明确
