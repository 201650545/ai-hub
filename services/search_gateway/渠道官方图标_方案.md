## 2. 统一规格（与已有图标体系一致）

- **格式**：PNG-32 透明底，512×512，主体占画布 72–85% 居中。
- **目录与命名**：`web\img\channels\<渠道id>.png`（如 `web\img\channels\deepseek.png`），id 与 `channels.py` 完全一致，全小写。
- **官方 logo 处理规则**：
  - 优先保留原始配色（品牌色是识别度的核心）；
  - 横版字标（如 "Groq" 字标）只取**徽记部分**，不带文字——24–38px 显示尺寸下文字不可读；
  - 源图为 JPG/带底 → 用亮度/色键抠图转透明（同生图任务书 §2 后处理流程）；源图为 SVG → 直接渲染 512 PNG；
  - 分辨率不足 512 的（多数 favicon 仅 16–64px）：**用生图 AI 按原图高清重绘**（这一步耗积分，是本任务主要成本点），而非简单放大。
- **版权边界**：官方 logo 仅用于本机/内网管理台标识渠道归属，属合理使用；不二次修改 logo 造型本身（只做抠图/缩放/重绘放大）。

## 3. 接入方式（前端改动极小，执行时由我做）

现状：`channels.py` 每个渠道的 `icon` 字段是 emoji，前端按 emoji 文本渲染。
方案：**不改 channels.py 数据结构**——前端渲染渠道图标处统一改为「图片优先、emoji 兜底」：

```js
// 伪代码：渲染渠道图标处
const img = `/img/channels/${cid}.png`;
// 探测存在则用 <img>，失败回退当前 emoji（与风格图标套同一探测模式，复用 _iconDirCache 思路）
```

- 后端 `_serve_img` 已支持子目录（2026-08-25 已上线），`web\img\channels\` 直接可访问，无需再改后端。
- 缺失文件渠道自动显示原 emoji，可分批交付、逐渠道替换。

## 4. 执行批次与成本估算

| 批次 | 渠道 | 方式 | 预估成本 |
|---|---|---|---|
| 1 | deepseek / zhipu / dashscope / modelscope / sensetime / xiaohongshu | 官网/GitHub 直接抓取 + 抠图 | 零积分，约 30 分钟 |
| 2 | openrouter / groq / siliconflow / opencode | 官网或 org 头像，清晰度不足的重绘 | 少量积分（≤4 张重绘） |
| 3 | agnes / zscc / zenmux | 品牌资产薄弱，大概率需重绘或定制字标 | 主要积分消耗（≤3 张） |

兜底规则：某渠道拿不到可接受清晰度的官方 logo 时，用「渠道名首字母 + 品牌主色圆形底」定制字标占位，并在验收汇报标注，不用低质量图凑数。

## 5. 验收标准（执行完成后按此核）

1. `web\img\channels\` 下 13 个 PNG 齐全、512×512、透明底、主体居中占比 72–85%；
2. 与官网现行 logo 视觉一致（逐张对照官网截图复核）；
3. 渠道管理页 13 渠道全部显示官方图标，24px 下可辨识；缺文件渠道正确回退 emoji；
4. 无水印、无文字残留、无白底杂边（沿用媒体任务书 §7 自检清单）。
