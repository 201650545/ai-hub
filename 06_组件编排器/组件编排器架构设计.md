# 组件编排器架构设计 v1.0

> 首个闭环场景：HTML 课件自动生成（含图片/视频资产填充）
> 文档性质：架构宪法。后续所有组件开发、任务派发以此为准。

## 1. 定位与核心范式

**这不是工作流引擎。** 工作流是人事先铺好铁轨、火车照着跑；本系统是人只定目的地和交规，车自己找路。

| 维度 | 工作流（n8n/ComfyUI） | 本系统（组件编排器） |
|------|----------------------|---------------------|
| 管线路径 | 人工预先连线 | AI 临场决策 |
| 组件角色 | 管线上的步骤节点 | AI 手里的能力工具（帮手） |
| 画布角色 | 编辑器 | 观察窗（直播 AI 的思考与工作过程） |
| 人的角色 | 搭建者 | 监工：定方向、定规范、定验证、定执行程度 |

**人的四个输入**：总方向与目标 → 执行规范与格式 → 验证机制 → 执行程度（自治档位）。
确认后，AI 开始自动化设计，全程在画布上直播。

## 2. 总体流程（两段式生成）

### 第一段：框架生成
1. 接收用户目标（如「制作 L27 课件」）与规范（七段式/铁律/verify 规则）
2. AI 生成 HTML 总框架（页面骨架、结构、文案）
3. AI 扫描框架，**标记媒体槽位**：哪页插图、插什么主题、哪页嵌视频
4. 每个槽位**同步生成资产指令**：图片槽位生成 AI 绘图提示词；视频槽位生成搜索关键词

### 第二段：资产填充
5. 图片槽位 → 图片组件：opencli 打开指定生图网站 → 注入提示词 → 等待生成 → 提取下载 → 存入课时文件夹 → 替换槽位
6. 视频槽位 → 视频组件：定位 B站视频 → 提取 BV 号 → 生成嵌入代码 → 替换槽位
7. 每完成一部分 → 自动截图预览 → 事件流推送画布

### 第三段：验证交付
8. verify 规则全量校验（页数/体积/残留/平衡/JS/答案分布）
9. 失败项回流重搭（换提示词/换站点/换视频源），通过后交付

## 3. 媒体槽位协议 v1

框架生成时，AI 在需要资产的位置写入结构化注释；填充器扫描 `status=pending` 的槽位逐个处理，完成后**替换注释为真实标签**。

```html
<!-- MEDIA:img id=p12_market topic="超市场景对话" prompt="A bright supermarket aisle, flat cartoon style, children's textbook illustration, warm colors" mode=download status=pending -->
<!-- MEDIA:video id=p30_song topic="英文数字儿歌" source=bilibili keyword="English number song kids" mode=embed status=pending -->
```

**字段规范**：

| 字段 | 必填 | 说明 |
|------|------|------|
| id | 是 | 全局唯一，同时也是资产文件名（`p12_market.png`） |
| topic | 是 | 槽位主题（供画布展示与校验） |
| prompt | 图片必填 | AI 绘图提示词（框架生成时一并产出） |
| keyword | 视频必填 | 视频搜索关键词 |
| source | 视频必填 | 来源站点，首期固定 `bilibili` |
| mode | 是 | `download`（下载本地）/ `embed`（链接嵌入） |
| status | 是 | `pending` → `done` / `failed` |

**替换规则**：
- 图片（mode=download）→ `<img src="./p12_market.png" alt="超市场景对话">`
- 视频（mode=embed, source=bilibili）→ B站 iframe 播放器（见 §5）

**资产存放**：媒体文件与 HTML **平铺在同一课时文件夹**（遵守课时目录铁律，不设子文件夹），文件名即槽位 id，避免冲突。

## 4. 组件规则卡规范 v1

组件是 AI 的帮手；规则卡是人对组件的约束与教学——「告诉它如何生成图片、方向是什么、怎么去做」。

```yaml
component: image_gen            # 组件类型
site: 豆包生图                   # 目标站点
session: doubao_image          # opencli 会话名
url: https://www.doubao.com/   # 入口
style_lock: "flat cartoon, 儿童教材插画风, 明亮色调"  # 风格锁，自动拼接到每条提示词
inject:
  fill_selector: "textarea"    # 提示词输入框
  submit: "keys:Enter"         # 提交方式
wait:
  timeout_s: 90                # 生成等待上限
  poll_js: "!!document.querySelector('img.result')"  # 就绪探测
extract:
  method: img_src | blob_canvas # 提取方式（blob: 需 canvas 转 dataURL）
  selector: "img.result"
fallback: [换提示词重试, 换备用站点]
budget:                        # 成本控制
  max_retry: 2
```

已规划的首批规则卡：

| 规则卡 | 站点 | 状态 |
|--------|------|------|
| image_gen_doubao.yaml | 豆包生图 | 待适配 |
| image_gen_chatgpt_mirror.yaml | 用户自建 ChatGPT 镜像（GPT Image） | 待用户提供 URL |
| image_gen_qianwen.yaml | 通义千问 | 待适配 |
| video_embed_bilibili.yaml | B站 | 本设计 §5 已定 |

**组件发现机制**：新站点经「勘探任务」验证 opencli 注入可行后，产出新规则卡加入注册表，AI 选件时可发现。

## 5. 视频组件：B站嵌入（已定案）

**决策**：不做视频生成（算力成本高），不做视频下载（版权与分发风险），**以 B站 iframe 嵌入为主**（大陆可访问、有官网链接、可正常播放）。

**嵌入模板**（响应式，预留合适页面空间）：
```html
<div class="video-slot" style="position:relative;width:100%;aspect-ratio:16/9;">
  <iframe src="//player.bilibili.com/player.html?bvid={BV号}&page=1&high_quality=1&danmaku=0&autoplay=0"
          scrolling="no" border="0" frameborder="no" framespacing="0" allowfullscreen="true"
          style="position:absolute;inset:0;width:100%;height:100%;"></iframe>
</div>
```

**处理流程**：
1. 按槽位 keyword 检索候选视频（B站搜索页 / AI 搜索引擎辅助选型）
2. 提取 BV 号，校验视频存在且可嵌入
3. 写入 iframe，替换槽位注释
4. 截图预览（首帧可见即通过）

**降级**：检索无结果或嵌入被禁 → status=failed + 画布提示，由用户定夺替换或跳过。

## 6. 图片组件：浏览器注入生图（已定案）

**技术路径**（复用 AI Hub 引擎适配模式）：
```
opencli browser <session> open <生图站点>
→ eval 注入提示词（fill_selector，style_lock 拼接）
→ submit（click 或 keys）
→ 轮询 poll_js 等待生成（上限 timeout_s）
→ 提取图片：
   - https: 直链 → 直接下载到课时文件夹
   - blob: 地址 → canvas.toDataURL() 转 base64 → 解码保存
→ 替换槽位 → 截图预览 → 事件推送画布
```

**已知风险与对策**：
| 风险 | 对策 |
|------|------|
| 生成队列/审核延迟 | timeout_s + 指数退避轮询 |
| 审核不通过 | fallback：改写提示词（去敏感词）重试 ≤2 次 |
| 站点改版选择器失效 | 规则卡集中维护，E2E 测试每日巡检 |
| 会话掉线 | 重跑绑定脚本（同 AI Hub 引擎模式） |

## 7. 执行程度（自治档位）

| 档位 | 行为 | 适用 |
|------|------|------|
| L1 全自动 | 跑完直接交付 + 全套预览截图 | 规范成熟后 |
| L2 关键节点确认 | 框架看一眼、槽位清单看一眼，其后全自动 | **首期默认** |
| L3 每步确认 | 每个槽位填充前询问 | 调试期 |

## 8. 画布观察窗

**性质**：只读观察 + 监控，不是编辑器。AI 的思考与工作过程的动态动画展示。

**事件流协议**（SSE，复用网关 `/api/unified_stream` 机制）：
```json
{"ts":"14:04:12","phase":"asset_fill","slot":"p12_market","event":"prompt_ready","detail":"超市场景对话"}
{"ts":"14:04:15","phase":"asset_fill","slot":"p12_market","event":"generating","site":"豆包生图"}
{"ts":"14:05:03","phase":"asset_fill","slot":"p12_market","event":"done","preview":"./shots/p12_market.png"}
{"ts":"14:05:03","phase":"asset_fill","slot":"p15_reading","event":"retry","reason":"审核未通过，改写提示词"}
```

**画布元素**：阶段时间线、槽位状态格（⏳/✅/⚠️/❌）、**每部分完成后的预览截图**、当前正在操作的浏览器画面（可选，opencli 截图）。

## 9. 验证闭环

- 结构校验：verify_courseware.py 既有规则（页数/体积/残留/div 平衡/JS/答案分布）
- 资产校验：槽位清零（无 status=pending/failed 残留）、引用文件存在、图片可解码、iframe BV 号有效
- 视觉抽检：每部分预览截图入档，用户画布上实时确认
- 失败回流：单项失败 → 按规则卡 fallback 重搭；多次失败 → 画布标红等用户裁决
