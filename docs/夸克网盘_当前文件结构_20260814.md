## 三、技术约束（后续操作必须遵守）

1. **官方 CLI 无 rename / delete 命令，但删除已逆向可用**：只能 `create-folder` / `move`。删文件/文件夹走逆向 `/open/v1/file/delete`，`action_type=1` = 移入回收站（保留期内可恢复，非永久销毁），已验证可用（见 `scripts/_delete.cjs` / `_batchdel.cjs`）。`action_type=4` 无效。删除用 `~1...` 或 hex fid 均可。
2. **list 接口根目录专用**：逆向 `/open/v1/file/list` 的 `pdir_fid` 对非根值无效（传任何子目录 fid 都返回根目录内容）。子目录枚举只能靠 `search`（全盘 + 索引延迟），故无法 API 级可靠穷举子目录内容。
3. **fid 稳定性（重要，本次踩坑）**：
   - `create-folder` 返回的 32 位 hex fid（目标文件夹）稳定，可用于 `move --target-fid`。
   - `search` 返回的 `~1...` 源 fid **在单次会话内稳定**，但**跨请求可能变化**（实测 `我的备份` 两次搜索拿到不同 fid）。
   - ⚠️ **`qk-list` 根目录返回的 `~1...` fid 每次请求都变**，绝不能跨请求/跨进程用于 `move`——本次第一次批量聚类就因此失败（仅 `我的备份` 等个别项漏移）。可靠做法是 **search 取源 fid 后立即 move（同进程）** 或用 **`move` 时传 hex 目标 fid + 源 fid 在同一次操作中取用**。
   - `search` 的 `parent_fid` 字段会随会话变化，不可跨请求复用；核验位置应看 `path` 字段（`0`=根，`0,<fid>`=在某文件夹内）。
4. **organize 行为坑**：`organize` 会把整理结果新建到 `来自：WorkBuddy` 包装层（而非原地），且对「深层子文件夹」只会搬其顶层项、漏掉更深层文件（考研即此例）。用它做整理后，务必把结果文件夹提到目标位置并补搬漏项。
5. **切勿按关键词搜索后整批搬**：`search` 是**全盘**匹配，会命中教资包、课本等其他位置的同名文件夹（如 `人教版高中英语`、`高中英语模拟卷` 等），盲目整批 `move` 会误搬非英语资料。
6. **⚠️ 搜索索引存在大量陈旧重复条目（本次删除重大发现）**：同一文件夹会被搜索索引多次记录，产生许多**物理上不存在**的「幻影 fid」（删除接口返回 `21001 文件找不到` 或 `23004 文件已删除`）。因此「搜索到 N 个」≠「真实存在 N 个」。可靠做法：① 取 fid 后**逐个用删除/移动接口试真实存在性**；② 删除后用删除接口二次请求复核（`21001` 即证明已移除）；③ 不要仅凭搜索数量判断规模。删除类操作务必**先确认真实数量再执行**，避免对幻影条目反复操作。

## 五、操作脚本留存（位于 skill `scripts/`，供复用）

本次为可靠聚类沉淀了以下辅助脚本（已验证可用）：
- `_getfid.cjs`：按精确文件夹名从 search jsonl 取根目录文件夹 `~1` fid（优先 parent_fid==0）。
- `_where.cjs`：搜索某文件夹并打印其当前 fid / parent / path（核验位置用）。
- `_movenow.cjs`：搜索→立即 move（同进程，规避 fid 跨请求失效），参数 `<文件夹名> <目标hex fid>`。
- `_movenow_root.cjs`：qk-list 取根 fid → 立即 move（同进程），参数同上。
- `_cluster.cjs`：一次性取全根 fid 并按映射批量聚类（⚠️ 仅适合 fid 稳定场景，本次因 qk-list fid 会变而部分失效，已弃用为主路径）。
- `_delete.cjs`：单文件/文件夹删除（逆向 `/open/v1/file/delete`，action_type=1 移入回收站），参数 `<fid> [action_type]`。
- `_batchdel.cjs`：批量删除（逐 fid 删除、逐个报状态、失败不中断），参数 `<fid1> <fid2> ...`。
- `qk-list.cjs`：根目录列举（逆向接口）。

> 注：`_dbg.cjs` / `_rootfids.cjs` 为调试脚本，可删。删除能力已补进 skill（之前 CLI 缺失），`_delete.cjs`/`_batchdel.cjs` 可长期复用。
