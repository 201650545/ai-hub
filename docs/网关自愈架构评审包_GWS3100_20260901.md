## 4. 已定版决策（两轮 GPT 镜像评审完成，令牌已验证）

> 全文存档在本机 `C:\Users\郭永涛\.tools\tmp\gw_stability_review_20260901.md`（Round1，令牌 GWS-3100-OK）与 `gw_memtool_decision_20260901.md`（Round2，令牌 GWS-MEM-OK）。评审方读不到该路径，以下为权威摘要。

### 4.1 架构定版（Round 1）

- **[P0] 生产端口唯一 owner = SCM/NSSM 服务**。Task Scheduler 只做"健康检查/拉起服务/告警"；WMI 脱壳只保留为临时救援工具，不再拥有生产端口。:3100 与 :3000 都服务化，各自独立虚拟服务账户。
- **[P0] 3102 补丁**：短暂重试（带退避）→ 仍失败则 fail-closed → 由外部 Sentinel 判断后恢复。**绝不自动 kill 未知 owner**；不按"python.exe + api_gateway.py"进程名判合法 owner。
- **[P0] Sentinel 必须看 HTTP readiness（不是只看 LISTEN 端口）**，且每次探测后写 heartbeat。:3000 的 7 分钟暖机窗口内**禁止**按"端口未开"判死；`_readiness_preflight()` 应移植到 :3000 且放在暖机工作之前。
- **[P0] 网关进程保持独立虚拟服务账户**：不跑 Interactive 任务（登出即死），也不改 SYSTEM（无必要提权面）。渠道 key 是明文 json 不依赖用户 DPAPI，网关进程无用户会话硬依赖（已确认）。
- **[P0] 告警不弹窗**；"看门者自身的死亡也要可发现"。

### 4.2 记忆工具定版（Round 2）

- **主通道 = ai-hub-memory 运行状态文件 + Agent 启动必检**：

```
Gateway → SYSTEM Sentinel → ai-hub-memory/global/runtime/*.json ← 主状态源
                          → Agent 每次启动强制检查              ← 主到达人
ControlPlane → 飞书（即时副通道，P1） → gateway-alerts.jsonl → Event Log（取证兜底，P2）
```

- 目录与文件（ai-hub-memory 仓库内，`global/runtime/` 需加入该仓库 .gitignore）：
  - `gateway-health.json` —— **只允许 Sentinel 写**，每分钟原子覆盖（临时文件+rename），内容含 `updated_at` / sentinel state / 两网关 readiness / pid
  - `gateway-monitor.json` —— ControlPlane 维护的交叉监控态（含 `sentinel_stale` 标记）
  - `gateway-alerts.jsonl` —— 追加式告警流水
- **看门者死亡可发现（交叉 heartbeat）**：Sentinel 每分钟刷 `gateway-health.json.updated_at`；ControlPlane 每 5 分钟检查 `now - updated_at > 3min` → 判 `SENTINEL_STALE` → append alerts.jsonl + 尝试飞书 + monitor 记 stale=true。反向：Sentinel 发现 ControlPlane 心跳死亡同样写 alerts。Agent 例会巡检 = 第三方裁决。
- TOOLS.md 增加一行启动必检纪律（读 `global/runtime/gateway-health.json`，stale/FAIL 即上报用户）。
