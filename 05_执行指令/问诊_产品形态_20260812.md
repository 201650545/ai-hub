# 问诊：AI Hub 产品形态选择（2026-08-12）

> 用途：发给 ChatGPT 做架构顾问，判断「总网关/分网关」未来最佳形态。
> 仓库背景：https://github.com/201650545/ai-hub（私有，可先读 README.md / 项目简述.md / TOPOLOGY.md 了解结构）

## 一、产品现状（3 个服务，均为本地 Python HTTP 服务）

| 服务 | 端口 | 定位 |
|------|------|------|
| 中央平台（总网关） | :8000 | FastAPI 门户：网关注册表（/api/gateways）+ 导航首页 + GitHub 项目收集 + 飞书同步 + 统计分析 + 资源清单，6 个 tab |
| 智能聚合网关 DS V4 CLI | :3000 | 独立运行网关：5 大 AI 搜索（元宝/豆包/Kimi/通义/MetaAI）+ LLM 渠道聚合，前端是「无限画布控制台」（用户自己修复的 UI） |
| 组件编排器画布 | :8791 | 课件自动生成的 SSE 直播观察窗（事件流实时渲染） |

三者关系：**总网关（:8000）注册并展示所有分网关**，点卡片跳转。

## 二、遇到的问题

1. **浏览器标签不稳定**：服务进程一直是稳的（curl 全 200），但浏览器标签页易被覆盖/关闭/操作漂移——用户体感「网关挂掉了」。
2. 用户疑虑：网页形态是不是不够好？要不要做成桌面程序？

## 三、用户身份与约束

- 教师 + 个人开发者，Windows 11，本地跑 Python 服务
- 已有「启动AIHub.bat」一键启动脚本雏形
- 核心资产全部是 HTTP 服务（网页本身最稳），不想重写业务逻辑
- 日常使用：打开浏览器访问这几个服务

## 四、候选形态（已内部评估）

| 形态 | 优点 | 缺点 |
|------|------|------|
| A. PWA 安装（加 manifest + sw，Chrome 点安装变独立窗口） | 零重写、今天可落地、不占标签 | 仍是网页本质，用户可能觉得「不够程序」 |
| B. Tauri 桌面壳（Rust 壳包现有网页成 .exe） | 最像正式软件、10MB 轻量 | 要写壳代码，多花开发时间 |
| C. Electron 桌面程序 | 生态成熟 | 100MB+ 重，吃内存 |
| D. 保持网页 + 书签 | 零成本 | 标签问题依旧 |
| E. 后端服务化（nssm/计划任务开机自启）+ 任意前端 | 服务永不掉 | 只解决后端，没解决入口 |

## 五、请 ChatGPT 判断的问题

1. **以我们的情况（本地个人使用、3 个 HTTP 服务、Windows、不想重写），哪种形态综合最优？** 为什么？
2. PWA 和 Tauri 壳的真实体验差异有多大？PWA 是否够用？
3. 有没有我们没考虑到的形态（如本地聚合桌面应用、浏览器插件、托盘常驻 + 一键弹出）？
4. 如果选桌面化，是否值得现在做，还是等产品功能更完整再做？（排序建议）
5. 对未来 1-2 年的演进路径给一个建议路线图。

> 期望输出：明确的推荐 + 理由 + 落地路径，不要模棱两可。
